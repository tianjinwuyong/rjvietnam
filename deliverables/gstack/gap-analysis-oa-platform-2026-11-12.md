## 1. 各成员核心结论

### 🔍 产品官（功能完整性）

- **核心判断：不是功能不齐，是可见性断层。** 48 个模块里 41 个没有基线权限，40 个账号里 33 个没有显式授权 —— 普通员工登录后只看到 7 个模块（公告/文件/请假/补卡/隐患/会议/工资条），其余全部 403。**开发阶段这属正常（还没铺权限），但它决定了一件事：现在所有"页面可用性验收"都只能证明管理员能打开，不能证明员工能打开。**
- **流程引擎只跑通了"体系文件"这一条**：33 个流程定义全部建好，但 `flow_instance` 229 条全是 2026-08 的 `DOC-*` 发行单，报销/请假/申购/品质异常/设备维修等 32 条流程**零实例** —— 这在开发期是"还没轮到的开发任务"，不是故障；但意味着这 32 条流程的审批链、条件分支、终态挂钩从未被真实数据走过一遍。
- **员工自助区整块缺失**：没有"我的考勤""我的假期余额""我的加班"页面，请假剩余额度只能去管理台看。这是**尚未开发**，不是坏掉。
- **配置满配但未行使**：考勤 2 规则/4 班次/67 节假日/14 假别齐备，薪资 18 薪级/21 项/53 参数齐备，但 `salary_structure`、`salary_structure_binding`、`salary_tax_profile` 全为 0 —— **计时薪的最后一环没接上**，属于"配置做完了、数据没录"。
- **一个真 Bug（与环评无关，随时该修）**：加班数据统计与薪资引擎都按 `status='approved'` 取数，但考勤代码写入的是 `confirm_status`，不存在 `approved` 值 —— 加班申请开关一打开，加班时长会全部归零。当前加班申请流程本身也还没建，所以现在修成本最低。
- **加分项**：三语覆盖达标（越南语缺的是别名不是界面）、越南法规配置精度高（10 项逐条对上法令）、时区处理正确（DB UTC / 页面 +07 / 班次偏移不双重转换）。

### 🛡️ 安全卫士（OWASP + STRIDE）

- **核心判断：水位 D（不及格但可修）。** 技术底子明显好于同类内部系统——SQL 全参数化、路径穿越防护实测有效、附件按归属授权、模块级闸门、密码 bcrypt(10)、`sys_api_key` 收得很紧、修掉了"带 `flow:config` 即成管理员"的老洞；24 个路由文件逐一核对，**没有一个裸奔接口**。这些在开发期就已经做对，是加分不是欠账。
- **短板 100% 集中在身份与账号生命周期**：登录失败锁定被人为关闭（`MAX_LOGIN_FAIL=0`，`checkLock`/`recordFail` 直接 return，连失败计数都不再累计）、`must_change_pwd` 只在**前端路由守卫**生效（后端 `authenticate` 完全不检查，直接打 API 可永久停在默认口令）、重置口令固定 `oa@123456`。**这三项开发期不影响你写代码，上线那天全部变成事故 —— 列入上线前必修。**
- **攻击链是完整的**：`admin/admin123` → `GET /api/users` 拿到全公司花名册（还带 `is_admin`、`must_change_pwd` 标注"谁是管理员、谁没改密"）→ 无限爆破其他账号 → 全程零痕迹（`auth_fail_counter` 恒 0 行、无登录审计表）。**开发期的现实风险不是"被攻破"，是"同一个局域网里的同事随手登进来改坏了你的开发数据"。**
- **传输层**：`0.0.0.0:8090/8000` 明文对外，CORS `origin:true + credentials:true` 反射任意 Origin，HSTS/X-Frame-Options/CSP/X-Content-Type-Options 全缺（仅 `/api/files/*` 补了 nosniff）。开发期可用，上线前必须收敛。

### ✅ 质量门神（工程质量与运维）

- **核心判断：下限扎实、上限缺失。** 单点细节中上水准——迁移有 sha256 checksum + 每文件一事务 + 失败即中止（128/128 已应用）、日志有 10MB×5 档轮转、静态资源缓存分层正确（index.html `no-store`、assets `no-cache`+ETag）、DB 强制 `timezone=UTC`、连"测试脚本误连生产库"都写了护栏。**但把这些点连起来的机制一个都没有**：无 CI、无 lint、无 typecheck、无测试 runner、无 git hook、无备份排期、无监控探针、无外发告警通道。
- **开发期的真 P0 只有一条：护栏漏了 `tools/`。** `db/index.js:74-83` 的 `detectScriptContext()` 只认路径含 `/scripts/`，`tools/` 下 30 个 `import src/db` 的脚本全部放行 ⇒ **37/84 个验收脚本直连开发库、且会 `INSERT`/`DELETE`**。在还没有生产数据的时候，这就是唯一会真的弄坏东西的地方。
- **另两条标 🟠 上线前**：① 灾备链路断开（备份停 11-07，单块 SSD 承载全部，`archive_mode=off` 无 PITR，`docs` 里 0 条恢复演练记录）—— 开发期丢了可以重做，上线后丢了没法重做；② 算钱链路（5 个 service、约 32 万字节）从未处理过一条真实数据、单测 0。
- **一个活的信号**：`err.log` 里 `[iqc] 待检同步有 2 条失败：fetch failed` 累计 **615 条**，无人处理、无人知晓 —— 这就是"没有告警"最好的证明，而且它与是否上线无关，现在就该知道。
- **发布模型**：前后端同进程，改一行后端 = 全站停机 **33 秒**（实测中位）—— 开发期这就是你每次改代码的等待成本，没有 staging 反而省事，所以标 🟡。
