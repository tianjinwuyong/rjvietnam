## 1. 各成员核心结论

### 🎯 产品评审员（功能策划）

- **模块定位**：周期性、可持续更新的工作台账，不是一次性单据。核心用户故事 5 条：员工周初填写、过程更新、周五提交、领导审阅推送、管理层汇总晨会。
- **架构判断（原话要点）**：「流程引擎的模型是一次性单据走完审批即结束；周计划是周期性产生 + 持续更新 + 节点汇报。硬塞进流程引擎会产生海量单据噪音，或把审批流用成记账本（反模式）。」→ 独立模块，复用通知/组织架构/RBAC/三语等基础能力。
- **状态机**：`DRAFT → SUBMITTED → READ / RETURNED`（RETURNED 修改后重交回 SUBMITTED，记录轮次）。提交后锁定条目（保证领导看到的是快照），退回解锁。过程中的进度更新只发生在草稿态——这是「过程更新、节点汇报」的关键。
- **进度口径建议**：**枚举制**（未开始/进行中/已完成/已延期），不用百分比。理由：工厂员工对"做完没有"的判断远比"完成百分之几"可靠，枚举三语翻译干净、移动端体验好；若坚持百分比可折中（枚举为主 + "进行中"展开选填滑条，不参与统计）。
- **完成联动**：「是否完成」勾选 = 单一事实源，与进度互为镜像，勾完成自动写实际完成时间；取消勾选需二次确认。
- **汇报闭环**：提交后推送领导（站内+飞书，带条目摘要）；领导侧三动作 **已阅 / 评语后已阅 / 退回**（不强求每周写评语，避免闭环变形式主义）；建议做轻量「团队周计划」汇总页（完成率、Q1 完成率、逾期名单、按周切换）。
- **上级解析**：复用部门 leader_id，兜底链为「本部门负责人 → 上溯有负责人的上级部门 → 总经理」，提交时**快照 leader_id**（防调岗影响历史）；解析链到顶（总经理）免提交、直接自阅闭环。

## 3. 交互与页面要点

1. **工作台入口卡片**：往 `/api/stats/overview` 追加周计划字段（接口注释允许"仅追加"）+ 外挂 JS 往首页 DOM 追加卡片（先例 oa-doc-drafts-hint.js）；侧边栏入口照抄 schedule-plan entry 模式。
2. **填写页**：条目表格增删改；紧急程度下拉 + 颜色标签 + 顶部象限计数条（自查"第一象限是不是塞太多"）；草稿自动保存。
3. **提交页**：显示解析到的直属上级（解析不到给出提示与兜底人）；提交后锁定。
4. **领导页**：待阅列表 + 已阅/评语/退回；退回必填原因。
5. **汇总页（轻量）**：部门每人一行（条目数/完成率/Q1 完成率/是否逾期/是否已阅），按周切换。
6. **提醒**：截止前 24h + 截止时，notify() 推送"本周周计划尚未提交"。

## 5. 分期建议

**MVP 一期**（跑通闭环）：工作台入口卡片 + 填写页（四象限/进度/完成联动/草稿自动保存）+ 提交（快照上级+推送+逾期标记）+ 领导待阅/已阅/评语/退回 + 历史列表 + 三语（**第一期就要**，越南员工是主要填写人群）+ 权限五件套。

**二期**：复制上周计划（工厂高频，强烈建议优先）、未完成项自动滚入下周、完整统计报表与 Excel 导出、移动端 H5 打磨、考核挂钩口径。
