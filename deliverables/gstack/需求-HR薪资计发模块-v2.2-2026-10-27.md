## 1. 模块范围

### 1.1 要解决的问题（三句话）

1. **薪酬结构写死在代码里**：加一个「高温补贴」要改代码、要发版、要回归测试，业务等不起。
2. **加班费只有 3 档倍率（1.5 / 2.0 / 3.0）**，但厂里实际按 **10 个时间段**计价：20:00 之后 1.0、22:00 之后 1.3、周日 2.0、假日 3.0、假日夜班 4.1……。时段边界（20:00 / 22:00 / 04:30 / 05:00 / 06:00）在系统里全部丢失，**同一份打卡既可能多算也可能少算，方向还不一致**。
3. **没有按时间段统计工时的能力**：无法回答「某人 3 月夜班共几小时、其中 05:00 后的延时几小时」，也无法给出 14 段工时明细给车间和财务核对。

## 2. 口径速查（**HR 必读，全篇 80% 的争议都出在这里**）

### 2.1 五个字母，记住就够

| 代号     | 中文      | 一句话定义                                       | 谁决定      |
| ------ | ------- | ------------------------------------------- | -------- |
| **G**  | 月薪基数    | = 基本工资 + 岗位（职务）津贴。**注意：不含生活补贴、燃油、满勤、绩效、工龄** | 工资架构     |
| **H**  | 时薪基数    | = `G ÷ 208`。**分母恒为 208（=26×8），不随月份变**       | 参数       |
| **B**  | 应出勤正班工时 | 这个月**本该上多少小时**。看日历和排班，**不看打卡**              | 日历 + 排班  |
| **W**  | 折算工时    | 各段工时 × 各段倍率，再加带薪假补的虚拟工时                     | 打卡 + 时段表 |
| **应发** | 应发工资    | `G + H × (W − B) + 津贴`                      | 上述全部     |

> **为什么 208 不能变**：若按当月天数算分母，2 月（19 个工作日）的时薪会比 7 月（27 天）**高 36.8%**，同一员工不同月份的加班单价不一样，员工一算就发现，无法解释。

### 2.2 一条公式

```
应发 = G + H × ( W − B ) + 津贴
```

**怎么理解**：`G` 是「上满 26 天就该拿的钱」，`H × (W − B)` 是「超出或不足 26 天的部分」。

- 正常上满 → `W = B` → 只拿 `G`
- 加班/夜班/周日/假日 → `W > B` → 多拿
- 缺勤/事假/迟到 → `W < B` → 少拿（**自动扣，不需要单独的扣款项**）

**这是全篇最重要的一句话**：缺勤不需要另外做「扣款」动作，公式自己会扣。系统里**没有**「缺勤扣款」「迟到扣款」这两个独立项目，只有一个「正班差额」。

### 2.3 八个标准算例（系统必须算出这些数）

`G = 9,000,000`，`H = 43,269.23`，日薪（8h）= 346,154。

**前提：实际只有两个班，都是 12 小时**——白班 08:00–20:00、夜班 20:00–08:00。每班 12 小时跨度，扣 1 小时用餐后计薪 11 小时，其中 **8 小时正班**（计入应出勤 `B`）、**3 小时延时**（按 1.5 倍另计）。

| 场景                        | B   | W     | `H×(W−B)`  | 应发             | 说明                          |
| ------------------------- | --- | ----- | ---------- | -------------- | --------------------------- |
| 白班 26 天（标准 12h 班）        | 208 | 325   | +5,062,500 | **14,062,500** | 每班 8h×1.0 + 3h×1.5 = 12.5 折算 |
| 2 月只有 19 个工作日，白班全勤       | 152 | 237.5 | +3,699,519 | **12,699,519** | 月薪部分照发，少的只是加班               |
| 夜班 26 天（标准 12h 班）        | 208 | 388.7 | +7,818,750 | **16,818,750** | 比白班多 2,756,250（夜班津贴 + 夜间加班） |
| 白班 26 天，全部延到 22:00       | 208 | 403   | +8,437,500 | **17,437,500** | 20:00–22:00 走 ⑪ 1.5，不是 1.0  |
| 7/10/12 月 27 天白班全勤       | 216 | 337.5 | +5,257,212 | **14,257,212** | 多一天只多延时（4.5h），正班 8h 不加钱    |
| 26 天月，请 4 天事假            | 208 | 275   | +2,899,038 | **11,899,038** | 少 4 班 = W 掉 50 折算h，自动扣，无扣款项 |
| 26 天月，4 天迟到 20 分钟        | 208 | 323   | +4,975,962 | **13,975,962** | 扣 4 × 0.5 = 2 折算h（首段 1.0）  |
| 26 天月，4 天早退 20 分钟        | 208 | 322   | +4,932,692 | **13,932,692** | 扣 4 × 0.75 = 3 折算h（尾段 1.5） |

> 这八行是**回归测试的黄金用例**。任何一次改动后，这八个数必须一字不差。§11.2 把它们展开成了可执行用例。
>
> ⚠️ **别把「白班 26 天」记成 9,000,000**。那是「只上 8 小时正班、不加延」的数（08:00–16:30）。标准班是 12 小时，26 天必然带 78 小时延时，所以满勤是 **14,062,500**。

### 2.4 关于「27 天」这条，必须说清楚

2026 年 7、10、12 月各有 **27 个工作日**（比 26 天多一天）。

- **公司口径**：**月薪部分按满勤发 `G`**（原话：「不管多少天，都是按照满勤」）。第 27 天的 8 小时正班不额外加钱。
- **但延时照给**：那天的 3 小时延时仍按 1.5 计，所以 27 天月的 `W` 比 26 天月多 12.5，而 `B` 多 8，净多 4.5 折算h（194,712 越盾）。全年只有 3 个月触发。
- **法律上是合法的**：法律按**周**算（每周 ≤6 天 × 8h = 48h，正好不超），第 27 天**不是周休日**，所以按 1.0 计正班不违反第 98 条。
- **系统留了一个开关**：参数 `quota_cap_hours` 默认空（不封顶）。若日后决定「27 天要连正班 8h 也多给」，改成 `208`，`W−B` 会自然多出 8h。**代价是这 3 个月缺勤不再扣款**（配额被封住，缺勤被包干吸收）。两者不可兼得，这是数学性质，不是实现选择。

### 2.5 时段倍率表（按班次定义，HR 只需知道「什么时间上、算几倍」）

**白班 08:00–20:00**（8h 正班 + 3h 延时）

| 段 | 时间          | 日型    | 倍率       | 含义                |
| - | ----------- | ----- | -------- | ----------------- |
| ① | 08:00–16:30 | 周一至周六 | **1.0**  | 正班 8h             |
| ④ | 16:30–20:00 | 周一至周六 | **1.5**  | 延时 3h（标准班自带的加班）   |
| ⑪ | 20:00–22:00 | 周一至周六 | **1.5**  | 延到深夜，仍是加班         |
| ⑫ | 22:00–06:00 | 周一至周六 | **2.15** | 延到凌晨，夜间加班（1.5×1.3+0.2） |
| ⑬ | 06:00–08:00 | 周一至周六 | **1.5** | 延到次日早上，仍是加班 |

**夜班 20:00–08:00**（8h 正班 + 3h 加班）

| 段 | 时间          | 日型    | 倍率       | 含义                |
| - | ----------- | ----- | -------- | ----------------- |
| ② | 20:00–22:00 | 周一至周六 | **1.0**  | 正班前段 2h（22:00 前无夜班津贴） |
| ③ | 22:00–04:30 | 周一至周六 | **1.3**  | 正班夜段 6h（含 0.3 夜班津贴） |
| ⑤ | 04:30–06:00 | 周一至周六 | **2.15** | 加班 1h            |
| ⑥ | 06:00–08:00 | 周一至周六 | **1.5**  | 加班 2h            |
| ⑭ | 08:00–20:00 | 周一至周六 | **1.5**  | 延到白天            |

**周日 / 法定假日**（按整日倍率，不分班次、不再叠加加班倍率）

| 段 | 时间          | 日型       | 倍率       |
| - | ----------- | -------- | -------- |
| ⑦ | 06:00–22:00 | **周日**   | **2.0**  |
| ⑧ | 22:00–06:00 | **周日**   | **2.8**  |
| ⑨ | 06:00–22:00 | **法定假日** | **3.0**  |
| ⑩ | 22:00–06:00 | **法定假日** | **4.1**  |

**五条要点**：

1. **周六 = 工作日（1.0）**，周日 = 休息日（2.0）。这两个不能混。
2. **同一个钟点，白班和夜班含义不同**：20:00–22:00 对夜班是正班（②1.0），对白班延时是加班（⑪1.5）；22:00 之后对夜班仍是正班（③1.3），对白班则是夜间加班（⑫2.15）。**所以倍率表必须按班次分开，不能只按钟点。**
3. 系统取「**表内倍率**」和「**法定下限**」里**高的那个**。现行 14 段全部合法，⑤⑧⑩ 略高于法定，对员工有利。
4. 倍率可维护、可版本化。改倍率**只影响未来月份**，历史月份重算仍用当时的版本。
5. ②③ 不计入加班上限（月 40h / 年 200h）；① 也不计。④⑤⑥⑪⑫⑬⑭⑦⑧⑨⑩ 计入。

### 2.6 用餐：4 段不计薪

| 用餐  | 时间          | 扣减   |
| --- | ----------- | ---- |
| 午餐  | 11:30–12:00 | 0.5h |
| 晚餐  | 16:30–17:00 | 0.5h |
| 夜宵  | 23:30–00:00 | 0.5h |
| 夜间餐 | 04:30–05:00 | 0.5h |

已由公司确认**不计薪**。系统按「实际在岗时间与用餐窗口重叠多久就扣多久」计算，**不是固定每天扣 0.5h**（不上班不扣、没跨到该时段不扣）。

> ⚠️ **法律风险已知并需书面化**：越南第 109 条要求「班中休息 ≥30 分钟（夜班 ≥45 分钟）**且计入工时**」。要合法规避，必须在**劳动合同 + 劳动规章**写明「用餐时间不计薪、员工可自由离岗」并留签收。见 §13.2 W1。

### 2.7 迟到与早退的扣法（按公司规则）

**迟到——砍的是班次头部，倍率 1.0**

| 迟到时长         | 扣多少工时      | 金额（H=43,269） |
| ------------ | ---------- | ------------ |
| ≤ 5 分钟       | **0**      | 0（视同准时）      |
| 6 – 30 分钟    | 0.5h       | 21,635       |
| 31 – 89 分钟   | 1.0h       | 43,269       |
| 90 – 119 分钟  | 1.5h       | 64,904       |
| 120 分钟以上     | 每满 30 分钟 +0.5h | —            |
| **单日上限**     | **4.0h**   | 173,077      |

**早退——砍的是班次尾部，倍率 1.5**（这是与迟到最大的不同）

| 提前时长         | 扣多少**折算**工时       | 金额（H=43,269） |
| ------------ | ---------------- | ------------ |
| 准点 / 拖班      | **0**            | 0            |
| **1 – 30 分钟**  | 0.5 × 1.5 = **0.75** | 32,452       |
| 31 – 60 分钟    | 1.0 × 1.5 = **1.5**  | 64,904       |
| 61 – 89 分钟    | 1.0 × 1.5 = **1.5**  | 64,904       |
| 90 – 119 分钟   | 1.5 × 1.5 = **2.25** | 97,356       |
| 120 分钟以上     | 每满 30 分 +0.5h × 1.5 | —            |
| **单日上限**     | 4.0 × 1.5 = **6.0** | 259,615      |

**四个关键点（不做错这四条，钱就不会算错）**：

1. **早退没有宽限**。迟到有 5 分钟容忍，早退没有——只要比计划早走就至少扣 0.5h。
2. **早退的 0.5h 要乘倍率**。班次尾部是 ④/⑥（1.5 倍），所以「少算半小时」实际是 0.75 折算工时。按 1.0 算只扣 0.5，**每人每次少扣 10,817 越盾**。
3. **不重复扣**。惩罚工时先减掉「本来就没算到的那段时间」：`当日折算 = 自然折算 − MAX(0, 惩罚折算 − 自然短缺)`。例：迟到 20 分钟 → 实际少 0.33h、惩罚 0.5h → 只额外扣 0.17h，当日合计正好少 0.5h。
4. **同日既迟到又早退，取较大者，不叠加**（避免一天被扣两次）。

> 早退必须先有「排班」。只排 8 小时（08:00–16:30）的人 16:30 走**不算早退**；排 12 小时的人 16:30 走才算。所以系统只在**有排班记录**时才计算早退，没有排班不猜。见 §13.1 T2。

### 2.8 社保与个税（越南现行）

**社保（个人 10.5%，公司 21.5%，工会费 1%）**

| 险种        | 个人   | 公司    | 基数             | 封顶          |
| --------- | ---- | ----- | -------------- | ----------- |
| 养老保险 BHXH | 8.0% | 17.5% | 基本 + 职务 + 生活补贴 | 20 × 官方参考工资 |
| 医疗保险 BHYT | 1.5% | 3.0%  | 同上             | 20 × 官方参考工资 |
| 失业保险 BHTN | 1.0% | 1.0%  | 同上             | 20 × 地区最低工资 |
| 工会费       | 1.0% | —     | 同上             | **不封顶**     |

**个税（居民，5 级累进）**

| 级 | 月应税所得        | 税率  | 速算扣除       |
| - | ------------ | --- | ---------- |
| 1 | ≤ 10,000,000 | 5%  | 0          |
| 2 | 10M – 30M    | 10% | 500,000    |
| 3 | 30M – 60M    | 20% | 3,500,000  |
| 4 | 60M – 100M   | 30% | 9,500,000  |
| 5 | > 100M       | 35% | 14,500,000 |

减除额：**本人 15,500,000 / 每人抚养 6,200,000**。非居民（外籍）**20% 单一税率**，不累进。

**免税收入**：只有「加班 / 夜班那部分溢价」免税，**正班工资不免税**。系统内置**两套算法**，用一个参数 `exempt_mode`（A 或 B）切换，**默认 B（与现行 Excel 一致）**：

| 时段 | 倍率 | 口径 A：只免溢价 | 口径 B：加班段全免（现行） |
| --- | --- | --- | --- |
| ① ② 正班 | 1.00 | 免 0 | 免 0 |
| ③ 夜班正班 | 1.30 | 免 0.30 | 免 0.30 |
| ④ ⑪ ⑬ 白班延时、⑭ 夜班延时 | 1.50 | 免 **0.50** | 免 **1.50** |
| ⑤ 夜班加班 04:30–06:00、⑫ 白班延到凌晨 | 2.15 | 免 **1.15** | 免 **2.15** |
| ⑦ 周日日间 / ⑧ 周日夜间 | 2.00 / 2.80 | 免 1.00 / 1.80 | 免 2.00 / 2.80 |
| ⑨ 假日日间 / ⑩ 假日夜间 | 3.00 / 4.10 | 免 2.00 / 3.10 | 免 3.00 / 4.10 |

> **两个口径差多少（白班 26 天，`G = 9,000,000`）**：A 免 39 小时 = **1,687,500**；B 免 117 小时 = **5,062,500**。**差 3,375,000 越盾/人/月**，全部落在个税基数上。
>
> **A 与 B 怎么选**：越南税法通常只免「加班工资中高出正常工资的部分」（即 A）。B 免得多、员工到手多，但**公司少代扣的个税，稽查时要自己补**。这不是系统能决定的事——**请财务 / 税务出一句话写进档案，之后 HR 改一个参数即可切换**。一期先按 B。
>
> 切换规则：**只对切换之后的月份生效，已发放的月份不回溯**（历史记录里存着当时用的是哪个口径，随时可查）。

### 2.9 最低工资（合规红线）

| 项          | 值                             | 校验时机                 |
| ---------- | ----------------------------- | -------------------- |
| 月最低工资（一类区） | **5,300,000**                 | 保存工资架构时**直接拦**，不等到发薪 |
| 折算小时最低     | **25,480**（= 5,300,000 ÷ 208） | 同上。**加班费时薪基数不得低于此**  |
| 实发下限       | ≥ 5,300,000                   | 算薪时校验，扣完不足则阻塞        |

> 示例 `G = 9,000,000` → 时薪 43,269，远高于 25,480，合规。但若给某岗位设 4,800,000，**架构保存不进去**——因为它的加班费会低于法定下限，算出来就是少付。



### 2.10 入职首月不扣，次月扣上月（**v2.2 新增**）

**一句话规则**：新员工**入职当月不扣**个税、社保、工会费；从**第二个月起扣第一个月那笔**，第三个月扣第二个月那笔，一直这样往后推。

**为什么这么定**：员工刚入职时，社保登记号常常还没下来、税务登记也还没完成，当月没法申报，所以先从工资里不扣。等第二个月手续齐了，再补扣回来。

**最重要的一条，HR 必须记住**：

> **公司第一个月照常申报、照常缴纳，只是"从员工工资里扣回"的时间晚一个月。**
> 不是"第一个月不交社保"。如果理解成不缴，员工社保就断档一个月——**影响他以后的退休金、医保报销、失业金**，而且社保机构查的是单位有没有申报，跟你什么时候从工资里扣没关系。
> 一句话记：**「首月不扣」= 公司先垫钱，不是不交钱。**

**看一张表就懂了**（`G = 9,000,000`，白班 26 天，社保个人 9,000,000×10.5% = 945,000，工会费 1% = 90,000，合计 **1,035,000**；该工资档个税为 0）

| 月份 | 应发 | 本月"应该扣"的（记进台账） | 本月工资单实际扣的 | 实发 |
| --- | --- | --- | --- | --- |
| 10 月（入职当月） | 14,062,500 | 1,035,000 | **0** | **14,062,500** |
| 11 月 | 14,062,500 | 1,035,000 | 1,035,000（**10 月那笔**） | **13,027,500** |
| 12 月 | 14,062,500 | 1,035,000 | 1,035,000（**11 月那笔**） | **13,027,500** |
| …… | …… | …… | …… | …… |
| **离职月** | 14,062,500 | — | 1,035,000（上月）+ 1,035,000（本月）= **2,070,000** | **11,992,500** |

**三条 HR 必须知道的边界**

| 情形 | 怎么处理 | 为什么 |
| --- | --- | --- |
| **离职** | 最后一张工资单**一次扣清**（上月那笔 + 当月那笔） | 不结清就变成公司自己垫的死账，人走了追不回来 |
| **月中入职**（比如 10 月 20 日入职） | 仍算"第一个月"，照样不扣 | 规则按**入职所在的自然月**算，与干了几天无关 |
| **停薪留职后又回来** | **不重新开始**，接着原来的节奏扣 | 否则员工可以靠反复离职复职，永远不交这三项 |

**两个会让人困惑的地方**

1. **实发金额不能直接跟 Excel 比**。Excel 是"当月扣当月"，本模块是"当月扣上月"，同一个月永远差一笔钱的量。要对账请用**「应发」**和**「累计扣款」**两条线分别比 —— 在职满 13 个月后，累计值完全相等，一分不差。
2. **上年 12 月那笔，次年 1 月才扣，但个税算上一年的**。年度汇算的时候归属年不能错，否则会少报一个月。

## 3. 业务流程（系统支持的五个环节）

```
① 【一次性配置】薪酬项目 → 工资架构 → 绑工号
        ↓
② 【每月月初】法定假日 + 工作日历 + 排班
        ↓
③ 【每天】打卡导入 → 异常处理（漏卡 / 多卡 / 归属日）
        ↓
④ 【次月 1–3 日】工时统计 → 工资试算 → 复核差异 → 提交审批
        ↓
⑤ 【发薪日】批次审批 → 发放 → 工资条 → 归档
```

| 环节     | 谁做           | 多久一次         | 系统要做的事             | 卡住会怎样                        |
| ------ | ------------ | ------------ | ------------------ | ---------------------------- |
| ① 配置   | HR 经理 + 薪酬专员 | 一次性（后续只微调）   | 项目字典、架构、绑定、审批      | 绑不上架构 → 该员工**算不出工资**         |
| ② 月前准备 | 考勤专员         | 每月 1 次（跨年更重） | 录节假日、确认日历、排班       | **日历缺一天就阻塞**，该日不出数（宁可晚发不可发错） |
| ③ 日清   | 考勤专员         | 每天 10 分钟     | 导入打卡、处理异常池         | 漏卡不补 → 该员工当月**少发 346,154/天** |
| ④ 月结   | 薪酬专员         | 每月 1 次       | 生成工时汇总 → 算薪 → 差异归因 | 差异未归因 → 不进入审批                |
| ⑤ 发放   | HR 经理 + 财务   | 每月 1 次       | 审批、导出、留档           | —                            |

**关键设计：异常只阻塞个人，不阻塞全厂。** 一个人漏卡，其他人照常出薪，该员工在批次里标「待处理」，HR 补卡后单独重算。

## 4. 角色与权限

| 角色                         | 能做什么                                | 不能做什么         |
| -------------------------- | ----------------------------------- | ------------- |
| **薪酬专员** `salary:manage`   | 项目字典、架构、绑定、参数费率、算薪、工资单、休假类型与台账      | 审批架构、审批批次     |

3. **任何配置变更都要记录「谁、何时、改了哪个字段、原值 → 新值、影响范围」**。

### FR-02 工资架构（P0）

**目的**：一个岗位一套薪资构成，可多套并存、可版本化、可审批。

| ID      | 需求                                         | 优先级 |
| ------- | ------------------------------------------ | --- |
| FR-02-1 | 可建多套架构（如「一线计时标准」「技术员」「外籍」），每套有编码 + 版本号     | P0  |
| FR-02-2 | 架构明细 = 选项目 + 填金额 / 比例 + 排序 + 是否上工资条        | P0  |
| FR-02-3 | 可「另存为新版本」，旧版本保留且**被历史月份继续引用**              | P0  |
| FR-02-4 | 提交审批 → 审批通过才可绑定；`created_by ≠ approved_by` | P0  |
| FR-02-5 | 编辑时右侧**实时试算**一个样例员工（改金额立刻看到应发变化）           | P1  |
| FR-02-6 | 保存时校验：基本 + 职务 ≥ 5,300,000，且折算时薪 ≥ 25,480   | P0  |

**关键规则**

- 时间段覆盖的是 **0–48 小时轴**，不是 0–24。跨天班次（22:00 → 次日 04:30）在轴上落到 22:00–28:30，不午夜切分。

- 免税系数 A / B 两套并存，参数 `exempt_mode` 决定用哪套（现定 **B**）。

**为什么 FR-04-8 必须是硬校验（有具体金额后果）**

若用餐窗口漏配 `04:30–05:00` 这一段，周日 / 法定假日的夜班（22:00 → 次日 06:00）会**少扣 0.5 小时**，每班多算 0.5h。按 ⑧ 段 2.8 倍、⑩ 段 4.1 倍折算：

| 段 | 应有计薪工时 | 漏配后算出 | 每班多算折算工时 |
|---|---|---|---|
| ⑧ 周日夜间 | 7.0h | 7.5h | +1.4h |
| ⑩ 假日夜间 | 7.0h | 7.5h | +2.05h |

按假日夜班算，每班多发 **88,702 越盾**（2.05 × 43,269）。一次节假日 30 人上夜班就是 266 万。**这不是小数点问题，是硬校验的理由。**

| FR-08-1 | 迟到判定：以**排班上班时刻**为准；无排班取**班次标准上班时刻**；两者都无 → 阻塞 | P0 |
| FR-08-2 | 阶梯：≤5 分免；6–30 分扣 0.5h；31–60 分扣 1.0h；每再满 30 分 +0.5h；**单日封顶 4h** | P0 |

**两个必须做对的算法细节**

1. **不能直接从 `W` 里减 0.5h**。迟到本身已经让工时少了一次，再全额减一次就是双扣。
   正确：`W_日 = 自然折算工时 − MAX(0, 惩罚工时 − 实际短缺工时)`

| 白班迟到 20 分钟 | 7.67 | 0.33 | 0.5 | 7.50 | 0.5h = 21,635 |

### FR-10 工资计算与工资单（P0）

**目的**：一键把「工时 + 架构」变成「应发 / 社保 / 个税 / 实发」。

| ID | 需求 | 优先级 |
|---|---|---|
| FR-10-1 | 按人 × 月生成工资单；支持单人、多人、全厂三种范围 | P0 |
| FR-10-2 | 工资单含：时薪、`W`、`B`、`W−B`、应发、免税收入、应税工资、社保基数、社保个人、工会费、应税所得、个税、实发 | P0 |
| FR-10-3 | 分项明细逐行可展开：项目、基数、倍率 / 费率、数量、金额、免税金额 | P0 |
| FR-10-4 | 每张工资单记录**规则快照**（用的哪版倍率表、哪版费率、哪版参数） | P0 |
| FR-10-5 | 状态机：草稿 → 已审批 → 已发放；**已审批后禁止静默覆盖** | P0 |
| FR-10-6 | 单人单月**试算**（不落库），HR 可调参数看结果变化 | P0 |
| FR-10-7 | 重算只覆盖草稿；已审批 / 已发放的走「更正单」 | P1 |
| FR-10-8 | 工资单显示异常标记：待补日历、漏卡阻塞、加班超限、含估算工时 | P0 |

**计算顺序（不可调换）**

```
① 取架构 → G = 基本 + 职务
② H = G ÷ 208
③ 读考勤 → 逐日逐段产出「计薪工时」，汇总 W（含带薪假补工时）
④ B = 日历上工作日应出勤工时之和（不封顶）
⑤ 应发 = G + H × (W − B) + 津贴
⑥ 免税收入 = H × 免税工时
⑦ 应税工资 = 应发 − 免税收入
⑧ 社保 = 分险种、各自基数、各自封顶
⑨ 应税所得 = MAX(0, 应税工资 − 社保个人 − 工会费 − 15,500,000 − 抚养人 × 6,200,000)
⑩ 个税 = 应税所得 × 税率 − 速算扣除
⑪ 实发 = 应发 − 社保个人 − 个税 − 工会费 − 其他扣款
```

**四条不可妥协的实现约束**

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | `H` 的分母**恒为 208** | 同人不同月加班单价不同，员工一算就发现 |
| 2 | `B` **只看日历和排班，不看打卡** | 缺勤不会自动扣，等于白送 |
| 3 | `B` **只累加工作日**，周日和假日一律不进 | 拿周日加班顶平日缺勤，每人每月少发 1,384,615 |
| 4 | 公式**没有第三项**、**没有独立缺勤扣款项** | 重复计价 / 同一天扣两次 |

**第 3 条的反例（务必写进测试）**：日历 22 个工作日，员工全勤（176h），另外 4 个周日各上 8h。

- 错误：`B` 把周日算进去 → `B = 208`，`W = 240` → 只付 `H×32` → 应发 10,384,615
- 正确：`B = 176`，`W = 240` → 付 `H×64` → 应发 **11,769,231**
- **差 32h = 1,384,615 越盾/人/月**

- 免税收入 ≤ 全部加班溢价（有缺勤的月份，上界放宽为 `H × W`）

- 社保个人合计 = 10.5%（除非触发封顶或下限）
- 实发 ≥ 0，且扣完 ≥ 5,300,000（不足则阻塞并提示）
- **递延校验（v2.2）**：① 每个 `status=pending` 的记录只能有**一条**对应下月的扣款，不得重复扣；② 离职月结算后该员工 `pending` 必须为 **0**；③ `Σ 每月计提 = Σ 已扣 + Σ 未扣`，三个数必须闭合

## 11. 验收标准

### 11.1 三层判定（**不写「逐笔一致」这种做不到的标准**）

| 层 | 校验内容 | 判定 | 不通过说明 |
|---|---|---|---|
| **第一层 结构自洽** | ①..⑩ 分段工时之和 = 计薪工时；`W` = Σ(段工时 × 倍率)；`B` = 日历工作日累加；日级明细可回算出全部合计 | **零容差，全量校验** | 切片 / 日历 / 归属日有错。**这层不过，后面不用看** |
| **第二层 公式解析** | 用同一组 `W`、`B` 代入公式 | 差额 = `H×(208−B)`，**残差 < 1 越盾**（`B` 可大于或小于 208，符号自动跟随） | 实现与规则不符（误加第三项、偷偷保留缺勤扣款） |
| **第三层 基线抽样** | 抽 30 人 × 1 个完整月，逐段人工核对工时与金额 | 差异**必须能归到 §11 的归因码**，无「原因不明」项 | 免税 / 社保 / 个税口径有错 |

**为什么第三层用抽样而不是全量**：全量逐笔比对的隐含前提是「有一套绝对正确的基准」。系统上线前不存在这样的基准——人工核算本身也可能错。抽样 30 人能覆盖全部日型、全部班次、全部津贴项，**足以证明口径正确**；全量则验证「无系统性偏差」。

### 11.2 必测用例（每条都要有明确的期望值）

### 11.3 上线门禁（四条全过才可切换）

1. 第一层结构自检 **100% 通过**（全量，不抽样）。
2. 第二层公式残差 **< 1 越盾**，覆盖 `B > 208`、`B = 208`、`B < 208` 三类月份。
3. **连续 2 个完整薪资周期双轨并行**（系统与现行手工核算同时出数，差异全部能归因）。
4. AC-01 ~ **AC-25** 全部通过，验收单归档。

## 12. 分期与优先级

### 第一期：算得对（20~23 人日）— **没有它一天都不能用**

| 内容 | 对应需求 |
|---|---|
| 全部新表 + 迁移脚本（幂等） | 支撑全部 FR |
| 14 段 + 4 用餐 + 12 薪酬项 + 14 休假类型 + 参数种子 | FR-01、FR-04、FR-09、FR-13 |
| 时段切片服务（0–48h 轴、用餐交叠、跨日） | FR-04 |
| 计薪引擎（`G + H×(W−B)`，无独立扣款） | FR-10 |
| 迟到早退阶梯 | FR-08 |
| 休假 `paid` 进 `W` | FR-09 |
| 试算 + 差异归因 + 明细导出 | FR-12 |
| **绑定名单导入通道** | FR-03 |
| 漏卡归约与阻塞 | FR-06 |

> 一期**不做业务界面**，但**必须做名单导入**——数百人的绑定不可能手写 SQL，缺此通道则一期产不出数据、无法验收。

### 第二期：配得动（15~18 人日）— **没有它业务不能自助**

项目字典、架构编辑器、工号绑定、时段维护、班次补字段、参数费率、14 段透视、休假台账、调薪留痕、影响面预览。

### 第三期：管得住（9~10 人日）— **锦上添花，可延后一个季度**

加班上限看板、日历强校验、年假治理闭环、批次审批、工资条导出、双轨报表。

**取舍原则：预算紧砍三期，不砍一期。** 一期数算不对，整套东西一天都不敢用；二期没时段维护，改倍率要找开发。三期晚一个季度不影响发薪。

**总计 44~51 人日。**

## 附录 B：一页纸公式卡（打印贴在 HR 工位）

```
G = 基本工资 + 职务津贴
H = G ÷ 208
B = 当月工作日应出勤工时之和（不封顶，不含周日 / 假日）
W = Σ(各段工时 × 该段倍率) + 带薪假补的工时
应发 = G + H × (W − B) + 其他津贴

免税收入 = H × 免税工时
应税工资 = 应发 − 免税收入
社保个人 = 分险种，各自基数，各自封顶
应税所得 = MAX(0, 应税工资 − 社保个人 − 工会费 − 15,500,000 − 抚养人数×6,200,000)
个税 = 应税所得 × 税率 − 速算扣除
实发 = 应发 − 社保个人 − 个税 − 工会费 − 其他扣款
```

**三个数记住就够**：`H = 43,269`、`日薪 = 346,154`、`半小时 = 21,635`（以 `G = 9,000,000` 为例）。
