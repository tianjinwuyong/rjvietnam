## 二、五条口径落在哪（可逐条验收）

| 口径 | 实现位置 | 验收方式 |
|---|---|---|
| 月薪制 `应发 = G + H×(W−B)` | `payroll-core.computeMonthSalary`（沿用） | 试算页：B=216、W=337.5 → 14,257,212 |
| 14 段倍率、按班次区分 | `payroll-core.sliceShift` + `attendance_time_band.shift_type` | 时段倍率页 14 行，白班/夜班各 5 段 |
| 迟到有 5 分钟宽限、早退无宽限，惩罚乘倍率 | `latePenaltyHours` / `earlyPenaltyHours` / `applyPunctualityPenalty` | 试算页填「早退 20 分」→ 少 0.75 折算工时 |
| 社保分险种封顶 | `computeInsurance` | G=60M 时：养老/医保基数封 46.8M、失业不封 |
| 个税先扣免税收入 | `computePit({ deductExempt })` | G=20M、B 口径：免税 11,682,692 → 个税 110,000（A 口径 499,423） |
| 首月不扣、次月补扣（递延） | `resolveFirstMonth` + `planDeferral` + `payroll_deferral` | 验证脚本：A 首月实发=应发、递延 1,035,000；B 正常扣 12,638,077 |
| R1 加班超限「只提示不拦」 | `buildWarnings` 的 `OT_MONTH_CAP` | 27 天月会出黄色提示，工资照发 |
| R2 免税 A/B 可切 | `salary_param.exempt_mode` + 界面下拉 | 「社保与参数」页切换后重算即生效，不改代码 |

## 四、HR / 财务上手五步

1. **补入职日期**：「社保与参数」页 → 入职日期列逐人填。**34 人目前全部为空**，不填就不触发首月递延。
2. **填工资结构**：仍走原「工资结构」页。目前库里只有 1 份 draft 结构且金额为 0，
   v2 引擎会直接拒绝计薪（报「没有可用的工资结构」）——这是有意的，宁可不发也不发错。
3. **导入打卡**：「考勤管理」页按模板导入（`employee_no / work_date / check_in / check_out`）。
4. **生成工资单**：「薪资核算」→ 概览 → 先点「试算全厂（不写库）」看人数与总额，再点「生成工资单」。
5. **确认**：核对无误后点「确认」。确认后工资单锁定，递延台账才真正记账；要改先「作废」。

## 六、与 v1 的关系（并存，不互相覆盖）

- 数据：同一张 `salary_record`，用 `engine_version` 区分（v1 为 NULL / `1.x`，v2 为 `v2.1.0`）。
- 接口：v1 在 `/api/salary/*`，v2 在 `/api/payroll/*`，各自独立的服务文件。
- 社保口径：v1 靠工资结构明细行（`insurance_personal` 等，`base_field=gross`，会把加班费算进基数）；
  v2 走 `salary_insurance_rate`，基数 = G（基本工资+岗位津贴）。**两者算出的社保会不同，v2 是设计口径。**
- 回滚：`98` 迁移末尾附了完整 DROP 语句；代码层删掉 `routes/payroll.js` 的注册即回到原状。
