# MES ⇄ WMS 领料单双向接口需求

> 提出方：WMS ｜ 日期：2026-10-31 ｜ 对接人：仓库 / IT
>
> 目标：**WMS 不再按工单自己算单**，改为直接接收 MES 已经开好、已经审批的领料单，单号、明细、下单人、批准人全部以 MES 为准。
>
> 同时：**WMS 发完料要把实际发料数据写回 MES**，MES 用它做工单结案。
>
> 即两个新接口：
> - `GET /api/itf/wms/issue/list` —— MES → WMS，领料单查询（第一节）
> - `POST /api/itf/wms/issue/{issueNo}/issued` —— WMS → MES，发料结果回写（第二节）

---

## 一、为什么要加这个接口

当前 MES 对外开放的接口（v1.0，2026-10-30）只有四个：

| 接口 | 用途 | 能不能满足"接领料单" |
|---|---|---|
| `GET /api/itf/wms/ping` | 探活 | — |
| `GET /api/itf/wms/mo` | 工单清单 | ✗ 只有工单，`issueNo` 只有一个字段 |
| `GET /api/itf/wms/mo/{moNo}` | 工单详情 | ✗ `issues[]` 无明细、无人员 |
| `GET /api/itf/wms/issue/pending` | 待领料工单 | ✗ 只给"还有缺口"的工单，给不到已开单的原始行 |

实测 `/issue/list`、`/picking`、`/picking-orders` 均返回 404。

结果就是：WMS 只能拿"工单 + 用料汇总"自己拼单，导致——

- 单号是 WMS 自己编的，和 MES 的领料单号对不上，仓库对单要人工核
- 明细是按 BOM 现算/按工段汇总的，不是 MES 领料单的原始行
- **拿不到下单人和批准人**，台账上审批人一列是空的，审计过不去
- 已经发完料的单拿不到（`/issue/pending` 只返回还有缺口的）

补一个领料单查询接口，以上四个问题一次解决。

---

## 二、接口定义

### 2.1 领料单列表（一次带明细）

```
GET /api/itf/wms/issue/list
```

请求头：

```
X-Api-Key: <密钥>       # 沿用现有 MES 下发给 WMS 的密钥
Accept: application/json
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `updated_since` | string | 否 | 增量起点，`2026-10-01`、`2026-10-01 08:00:00` 均可。**WMS 按这个轮询** |
| `status` | string | 否 | 按状态过滤，如 `approved`、`closed` |
| `mo_no` | string | 否 | 只取某张工单的领料单 |
| `page` | int | 否 | 默认 1 |
| `page_size` | int | 否 | 默认 50，**上限 500** |

响应（结构与现有 `/mo` 保持一致，WMS 侧不用改解析逻辑）：

### 2.2 字段说明

**单头**

| 字段 | 必填 | 说明 |
|---|---|---|
| `issueNo` | **是** | MES 领料单号，**WMS 用它做唯一键**，重复同步只更新不重复建单 |
| `moNo` | **是** | 对应工单号，WMS 用工单号关联产品、数量 |
| `workSection` | 建议 | 工段：`SMT` / `DIP` / `组装` / `包装` / `辅料`。没这个字段 WMS 只能归到默认工段 |
| `status` | **是** | 见下方状态字典 |
| `productCode` / `planQty` | 否 | 工单产品与计划数，方便核对 |
| `createdBy` | **是** | **下单人**，格式 `{"code":"工号","name":"姓名"}`；没有工号可以只给 `{"name":"姓名"}` |
| `createdAt` | 建议 | 下单时间，`YYYY-MM-DD HH:MM:SS`（+07:00） |
| `approvedBy` | **是** | **批准人**，格式同上。未审批的单可为 `null` |
| `approvedAt` | 建议 | 批准时间 |
| `remark` | 否 | 备注 |
| `items[]` | **是** | 领料明细行 |
| `updatedAt` | **是** | 最后更新时间，增量同步基准 |

**明细行**

| 字段 | 必填 | 说明 |
|---|---|---|
| `materialCode` | **是** | 物料编码，WMS 按它匹配主数据 |
| `materialName` / `spec` / `unit` | 建议 | 名称、规格、单位；WMS 没有该物料时用这些字段建临时行 |
| `reqQty` | **是** | 本单申请数量 |
| `issuedQty` | 建议 | 已发数量，WMS 用来判断是否已发完 |
| `mpq` / `posRef` | 否 | 最小包装量 / 位号，发料核对用 |

### 2.3 状态字典

请返回英文枚举（中文可放 `statusText`），WMS 按这个映射：

| 值 | 含义 | WMS 处理 |
|---|---|---|
| `draft` | 草稿 / 未提交 | 不接 |
| `pending_approval` | 待审批 | 可选接，进「领料审批」 |
| `approved` | 已审批待发料 | **接，进发料管理** |
| `partial` | 部分发料 | 接，可由 WMS 发料结果回写 |
| `closed` | 已发完 / 已关闭 | 接（只读，用于对账） |
| `cancelled` | 已取消 | 不接（已接的置为取消） |

> 如果英文枚举不好改，返回中文（`待审批` / `已审批` / `已发料` / `已取消`）也可以，请在文档里明确写法，WMS 做一张映射表。

## 三、发料结果回写（WMS → MES，工单结案用）

现有接口是只读的（文档第七节：「WMS 不能通过它改 MES 数据」），所以回写必须新开一个写接口。
**没有这个接口，MES 工单结案只能靠人工二次录入。**

### 3.1 接口

```
POST /api/itf/wms/issue/{issueNo}/issued
X-Api-Key: <密钥>
Content-Type: application/json
```

### 3.2 请求体

```json
{
  "issueNo": "LL2610310001",
  "moNo": "26101001204",
  "wmsPickingNo": "PK202610310001",
  "workSection": "SMT",
  "eventType": "issued",
  "issuedAt": "2026-10-31 10:22:39",
  "issuedBy": { "code": "RJ116", "name": "CAO THỊ PHƯỢNG" },
  "idempotencyKey": "wms:PK202610310001:issued",
  "items": [
    {
      "materialCode": "0.00.00.01.0237B-HF",
      "materialName": "贴片电阻",
      "unit": "PCS",
      "actualQty": 200,
      "batchNo": "B261015",
      "reelNo": "R000123"
    },
    {
      "materialCode": "0.00.00.01.0435L-HF",
      "materialName": "贴片电容",
      "unit": "PCS",
      "actualQty": 80,
      "batchNo": null,
      "reelNo": null
    }
  ]
}
```

### 3.3 字段说明

| 字段 | 说明 |
|---|---|
| `issueNo` | **路径参数**，MES 领料单号 |
| `moNo` | 工单号 |
| `wmsPickingNo` | WMS 侧领料单号，MES 用来区分「同一张 MES 单的多次回写」 |
| `workSection` | 工段：SMT / DIP / 组装 / 包装 |
| `eventType` | 本期固定 `issued`（实发完成）。预留 `received`（产线签收） |
| `issuedAt` | 发料完成时间，`YYYY-MM-DD HH:MM:SS`（+07:00） |
| `issuedBy` | 发料人，`{code,name}`，同领料单的人员格式 |
| `idempotencyKey` | **幂等键**，格式 `wms:{wmsPickingNo}:issued` |
| `items[].materialCode` | 物料编码 |
| `items[].actualQty` | **实发数量**（不是申请量） |
| `items[].unit` | 单位 |
| `items[].batchNo` | 批次号，**可能为 null**（该物料发料时不带批次） |
| `items[].reelNo` | SMT 盘号，非盘装料为 null |

### 3.4 幂等与重试（这一节请务必按约定实现）

WMS 是**至少一次投递**，网络超时、MES 重启、5xx 都会重发，所以：

1. **按 `idempotencyKey` 幂等**：建议 MES 建一张 `itf_wms_issue_writeback` 接收表，`unique(idempotency_key)`；
   收到重复 key 直接返回 `code:0`，**不要重复记账**。
   这个 key 由 WMS 生成，格式 `wms:{wmsPickingNo}:issued:v{版本}`（版本 = 该单最后一次变更的毫秒时间戳），
   MES 只做去重，**不要解析 key 内容**。
2. **同一张 MES 单会收到多次回写**：WMS 按工段拆单，一张 MES 领料单可能对应 3 张 WMS 单（SMT/DIP/组装）。记账规则：
   - 以 `wmsPickingNo` 为**分片键**，同一 `wmsPickingNo` 再来一次视为**覆盖**（取最新一条），**不累加**
   - 结案判断时，把该 `issueNo` 下所有 `wmsPickingNo` 的最新值按物料求和，再和 `reqQty` 比
   - 千万不要按「收到几次请求」累加，否则补发一次就多算一遍，会导致提前结案
3. **WMS 重试策略**：失败后按 1 → 2 → 5 → 15 → 30 → 60 分钟退避，最多 8 次；超过后置为失败并告警，可在 WMS 后台手动重推
4. **`batchNo` 允许为空**：为空时按物料累加即可，不要当成错误丢掉整条回写
5. **只推「实发」**：本期 `eventType` 固定 `issued`，内容是发料完成时的实发数量（不是申请量）。产线签收差异、退料暂不回写，
   后续要补时用 `eventType=received` / `returned` 区分，MES 侧按 (issueNo, wmsPickingNo, eventType) 分开记

### 3.5 响应

```json
{
  "code": 0,
  "message": "ok",
  "requestId": "…",
  "data": { "issueNo": "LL2610310001", "wmsPickingNo": "PK202610310001", "accepted": true }
}
```

幂等重复（key 已处理过）也返回 `code:0`、`accepted:true`，不要返回 409。
错误码沿用现有：`40101` 密钥错、`40404` 领料单不存在、`50001` 内部错误。

### 3.6 MES 侧拿到后怎么结案

WMS 不推「可结案」信号，由 MES 自己判断。建议口径：

- 该工单下所有领料单，每个物料的 `Σ actualQty` 覆盖 `reqQty`（或达到 MES 允许的发料容差）→ 自动/提示可结案
- 有短发（`Σ actualQty < reqQty`）→ 不允许结案，或走超发/欠发审批
- 结案后 MES 领料单状态置 `closed`，WMS 下次查询会同步成已发料

> **职责边界（2026-10-31 确认）**：结案只在 MES 做。判定按**领料单来源**：
> 只要这张工单下存在未取消的 MES 领料单，WMS 就**不接受**在本地执行下发/撤回/结案/取消（接口返回 400）；
> WMS 自己按 BOM 开的领料单（`source=manual`）仍沿用原有 WMS 流程，与接入 MES 前一致。
> WMS **不会**调用任何 MES 的工单状态写接口，WMS 侧工单状态仅由同步映射 MES 状态得到
> （已关闭 → `closed`，已取消 → `cancelled`），因此 MES 结案后无需通知 WMS，下一轮同步即自动对齐。

## 四、WMS 侧拿到后会怎么做

1. 定时（默认 5 分钟）调 `/issue/list?updated_since=上次最后一条 updatedAt`
2. 按 `issueNo` 幂等落库：`status=approved/partial/closed` 的直接进「领料单 → 发料」列表，无需 WMS 再审一次
3. `createdBy` → 申请人，`approvedBy` → 审批人，`approvedAt` → 审批时间，备注写「MES 同步」
4. 工号先在 WMS 账号里按工号/账号匹配；匹配不到按姓名匹配；都匹配不到时保留 MES 的名字写在备注里，并提示管理员补账号
5. 明细按 `materialCode` 匹配 WMS 物料主数据；未建档的照单录入并高亮提示，不阻塞发料
6. **发料完成**（该 WMS 单所有行实发到位）→ 写一条待回写记录，由后台任务按 3.1 推给 MES；
   逐单推送，不攒批量，MES 那边能实时看到进度
