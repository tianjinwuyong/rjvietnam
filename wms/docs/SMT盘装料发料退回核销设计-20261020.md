# SMT 盘装料（Reel）发料—余料退回—工单核销 流程设计

**日期**：2026-10-20
**适用**：贴片电阻、电容、电感等按整盘（Reel）领用、按盘退库的物料
**现状**：领料按数量扣账，发出即视为消耗；退料按物料数量回库，无法对应到具体盘

---

## 1. 现状的问题

| 环节 | 现在怎么做的 | 问题 |
|---|---|---|
| 收货 | 一箱一码（六段码，含流水号） | 库存表按「物料+库位+批次+状态」合并，多盘并成一行 |
| 发料 | 扫码/录入数量，扣库存 | 系统不知道发的是哪一盘，只记数量 |
| 生产 | 无账务动作 | 盘在产线，系统仍认为已消耗 |
| 退料 | 按物料+数量退回，重新入库 | 退回来的料与原来那盘对不上，批次/流水号丢失 |
| 工单结案 | 领料数量即视为消耗 | 剩余料不退就一直算消耗，成本虚高、账实不符 |

核心缺口：**没有「盘」这一层的账**。数量对得上，实物对不上。

---

## 2. 目标流程（推荐）

```
收货贴盘号 → 整盘发料（盘在产线）→ 生产消耗 → 余料按盘退回 → 工单结案核销
```

1. **收货**：每盘一个唯一盘号（现有六段码第 6 段 / label_no），记录数量。
2. **发料**：仓管扫盘号，整盘发出（数量取标签数量，不允许改）。
   系统写一条「发料盘」记录：盘号、数量、领料单、工单、工段、原库位。
   库存按数量扣减；盘状态 = `issued`（在产线）。
3. **生产**：不做实时扣账，盘装料按盘管理，产线只负责保管。
4. **退料**：换线或工单完工，余料退回仓库。仓管扫同一盘号，录退回数量：
   - 库存 + 退回数量（回到指定库位）；
   - 该盘 `returned_qty += 退回`，`consumed = issued - returned`；
   - 全部退完则盘状态 `closed`。
5. **工单结案核销**：工单实际用料 = Σ 各盘 `consumed`；
   与 BOM 标准用量对比，输出「超耗 / 节约」；
   未退回的盘按「全部消耗」处理，并在结案前提示确认（防止漏退）。

### 关键规则

- 一盘一码；**同一盘可多次退回**，累计 `returned_qty`。
- 退回数量不能超过 `issued - returned`；消耗不能为负。
- 发料数量以标签为准，不允许手工改大（防止一盘领出两盘的量）。
- 盘点仍按汇总行，但盘号层可追溯；工单结案前必须处理所有未结盘。

## 3. 数据模型

新增一张盘级流水表（不改现有库存结构，风险最低）：

```sql
CREATE TABLE picking_reel (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  picking_id      uuid NOT NULL,          -- 领料单
  picking_item_id uuid NOT NULL,          -- 领料明细行
  work_order_id   uuid NOT NULL,
  material_id     uuid NOT NULL,
  reel_no         varchar(100) NOT NULL,  -- 盘号（label_no / 六段码第6段）
  batch_no        varchar(100),
  from_location_id uuid,                  -- 发料库位
  issued_qty      numeric NOT NULL,
  returned_qty    numeric NOT NULL DEFAULT 0,
  consumed_qty    numeric NOT NULL DEFAULT 0,
  status          varchar(20) NOT NULL DEFAULT 'issued', -- issued / returned / closed
  issued_at       timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
  issued_by       user_profile,
  returned_at     timestamptz,
  returned_by     user_profile,
  remark          text,
  UNIQUE (picking_id, reel_no)            -- 同一单同一盘只发一次
);
```

退料侧：在现有 `production_return` 增加 `reel_no`（或明细表加），
退料时按盘号匹配 `picking_reel`，回写 `returned_qty`，不新开流程。

工单侧：结案时按 `work_order_id` 汇总 `SUM(consumed_qty)` 作为实际用料。

## 4. 与现有功能的关系

| 现有能力 | 复用方式 |
|---|---|
| 扫码发料（labelNo/labelQty） | 直接把这两个字段落 `picking_reel`，不用改扫码逻辑 |
| 按箱拆料（留库 4900 等） | 拆出的「留库」仍按箱管理；盘料整盘发出，不拆 |
| 生产退料 + IQC | 退料单加盘号，退料入库后回写盘流水 |
| 工单用料/成本 | 结案时用盘流水核销，替代「领料即消耗」 |
| 库存查询/盘点 | 不变（仍按汇总行），盘级明细在 `picking_reel` 查 |

## 5. 实施分期

**一期（建议先做，风险可控）**
1. `picking_reel` 表 + 发料时落盘（扫码即写）。
2. 退料增加「按盘退回」模式：扫盘号 → 带出物料/批次/已发/已退 → 录退回数量 → 回库并回写。
3. 工单结案核销报表：每张工单的盘、发出、退回、消耗、与 BOM 对比。
4. PDA 增加「退料扫盘」入口。

**二期（彻底方案）**
- 库存唯一键加入 `label_no`（一箱一行），收货、调拨、盘点、MRB 全链路按箱取数。
- 收益：库存行与盘号一一对应，盘级账实彻底对齐；代价：改造面大，需要完整回归。

---

## 6. 需要业务确认的点

1. 盘装料发料是否**必须整盘**（不允许改数量）？还是允许拆盘？
2. 余料退回是否必须**扫原盘号**？找不到盘号时是否允许按物料退回（降级）？
3. 工单结案时，未退回的盘按「全部消耗」是否可接受？还是必须先退盘才能结案？
4. 超耗是否需要审批（超过 BOM 一定比例触发）？
