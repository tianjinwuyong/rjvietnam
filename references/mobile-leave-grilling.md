# 员工手机请假/报休/替岗 — Grill Session Notes

## Q1: 员工提交请假后，审批流怎么走？

**选项：**
- A：员工提交 → 班组长审批 → 直接生效（无HR复核）
- B：员工提交 → 班组长审批 → HR复核 → 生效
- C：员工提交 → 班组长审批 → 如需替岗则通知被替岗人确认 → 生效
- D：员工提交 → 班组长判断是否需要替岗 → 需要时触发替岗流程 → 班组长+HR双签生效

**推荐答案：C**
理由：替岗涉及他人班次，被替岗员工应有知情确认权；普通请假班组长一级足够。

## Q2: 请假/替岗的消息通知走什么渠道？

- **A**：只发站内通知（系统内消息中心）
- **B**：站内 + 微信/企微（企业微信）
- **C**：站内 + 微信/企微 + 短信（SMS）
- **D**：站内 + 微信/企微 + 短信 + 纸质假条（工厂存档）

推荐：**B**（越南工厂工人主要用手机，企微/微信是最高触达率的渠道；SMS成本高，纸质效率低）

*grilling continue...*

## Q3: 请假天数怎么计算？是否需要班组长现场核验？

- **A**：员工填日期，系统自动算天数，班组长审批时只看天数合理性
- **B**：员工填日期 + 上传附件（医院证明等），系统算天数，班组长审批时必须核验附件
- **C**：员工填日期 + 系统算天数，但3天以上的请假必须有线下核验记录（签字）
- **D**：员工填日期 + 系统算天数，班组长可要求现场核验，但不做强制要求

推荐：**C**（3天是合理阈值——1-2天班组长可以判断；3天以上需线下签字留痕，符合越南劳工法规要求）

*grilling continue...*

## Q4: 替岗申请成功后，被替岗人需要做什么操作？

- **A**：系统自动通知被替岗人，无需任何操作，默认同意
- **B**：系统通知被替岗人，被替岗人必须在手机上点"确认替岗"才能生效
- **C**：系统通知被替岗人，如果24小时内未拒绝则自动生效
- **D**：系统通知班组长，由班组长代替被替岗人确认

推荐：**B**（明确知情同意，被替岗人有最终决定权；点确认才生效，不同意可拒绝）

*grilling continue...*

## Q5: 员工当天临时请病假/急假，来不及走完整套审批，怎么处理？

- **A**：不允许，临时请假也必须走完审批流程
- **B**：员工提交申请后系统自动发送"紧急待审批"通知给班组长，班组长在手机上即时审批，生效后员工凭系统通知过门禁
- **C**：员工提交后系统生成临时凭证（电子假条），班组长电话确认后系统补审批记录
- **D**：员工告知班组长口头请假，班组长在系统外处理，系统不做要求

推荐：**B**（系统内紧急审批通道 + 凭系统通知过门禁，兼顾合规和时效；C的口头确认无记录风险大）

*grilling continue...*

## Q6: 请假/替岗的数据如何在 MES 系统中体现？不上班那天还会在工位上显示"待岗"吗？

- **A**：员工手机请假审批通过后，MES系统自动同步该员工当天的工位状态为"请假/替岗"，过站扫描时不拦截（灰色待岗显示）
- **B**：员工请假/替岗生效后，MES系统自动释放该员工的工位，其他人可以被分配到该工位
- **C**：员工请假/替岗生效后，MES不做任何处理，只有班组长知道，生产正常进行直到过站时才发现人不在
- **D**：员工请假/替岗生效后，MES系统通知班组长，班组长手动重新分配工位

推荐：**B**（MES自动释放工位是最合理的方式——请假生效=人不在=工位应该可以被重新分配；A的灰色待岗可能会误导排产）

*grilling continue...*

## Q7: 年假/病假等有上限的假期类型，系统如何处理余额不足的情况？

- **A**：系统不管控余额，员工随便申请，由HR人工审核时判断余额是否足够
- **B**：员工申请时系统实时显示当前剩余天数，请假天数不能超过剩余天数（超过时禁止提交）
- **C**：员工可以超额申请，但提交后系统提示"余额不足"，班组长审批时综合考虑
- **D**：系统按自然年自动清零/恢复年假，余额实时显示但不做强校验（只提示）

推荐：**B**（余额不足时禁止提交是最简洁的防错机制——不让员工做无用功，也减少班组长和HR的人工解释成本）

*grilling continue...*

## Q8: 员工取消/撤回请假申请，什么条件下允许？

- **A**：任何时候都可以撤回，只要审批还没最终通过
- **B**：班组长点击"审批"之前可以撤回；一旦班组长已点审批（无论通过还是拒绝），不可撤回
- **C**：班组长审批通过之前可以撤回；已通过的请假如需取消，必须走新的销假流程
- **D**：只有未读的申请可以撤回；班组长已查看的不可撤回

推荐：**C**（审批通过后如需取消=新的销假流程，防止员工循环请假/销假套取额外假期；A太过宽松，D太过严格）

*grilling continue...*

## Q9: 替岗申请中，替岗人和被替岗人的考勤分别怎么记录？

- **A**：替岗人：正常打卡记录在该班次；被替岗人：该班次自动记为"请假"（不扣余额）
- **B**：替岗人：正常打卡；被替岗人：系统标记为"替岗"（不记为请假也不记为出勤，属于特殊状态）
- **C**：替岗人：正常打卡并在备注中注明替岗；被替岗人：记为"请假"（扣年假/病假余额）
- **D**：替岗人：正常打卡；被替岗人：系统标记为"替岗"，由班组长在月底统一调整考勤

推荐：**A**（替岗是工作安排，被替岗人无需请假流程，该班次不扣余额是最合理的；B的特殊状态会造成月底考勤统计混乱）

*grilling continue...*

## Q10: 员工提前请假（还没到请假日期），审批通过后请假当天还需要做什么操作吗？

- **A**：不需要任何操作，系统在请假日期自动生效，员工当天无需打卡，系统自动记为"请假"
- **B**：需要员工当天点"确认请假"按钮，系统才记为请假；不点则记为旷工
- **C**：需要员工当天先打卡（人脸识别），然后系统自动识别当天有请假记录，显示"请假"状态
- **D**：不需要操作，但班组长可以在当天对已审批的请假进行"取消"操作

推荐：**A**（提前请假的意义就是当天不需要任何操作——减少员工操作负担；D的班组长取消权需配合通知机制，否则员工到了才发现请假被取消会有纠纷）

*grilling continue...*

## Q11: 报休（先销假后补假条）是什么场景？系统怎么支持？

- **A**：报休 = 当天临时有事无法事先请假，事后补交医院证明/家长联系记录等附件，系统记录为"先休后补"，不按旷工处理
- **B**：报休 = 员工当天请了半天假但忘打卡，事后申请补打卡记录，系统按请假处理
- **C**：报休 = 员工因急事临时离岗，事后补填"临时外出单"，系统记为带薪假期
- **D**：报休 = 员工因加班调休，先用OT时间再补请假申请，系统自动抵扣OT余额

推荐：**A**（"报休"在工厂的常见含义是临时急假来不及走审批流程，事后补附件证明；这是越南工厂工人常见场景——孩子生病、家人急事等）

*grilling continue...*

## Q12: 员工提交的请假/替岗申请，需要在数据库中留痕多久？导出什么格式？

- **A**：保留1年，支持导出 Excel，方便HR年终汇总
- **B**：保留2年（越南劳动法规定），支持导出 Excel + PDF（具有法律效力）
- **C**：保留5年，支持导出 Excel（工厂内部存档）
- **D**：永久保留，支持导出 Excel + PDF + 纸质打印归档

推荐：**B**（越南劳动法规定考勤记录保留≥2年；PDF具有法律效力，Excel仅供内部汇总）

*grilling continue...*

## Q13: 员工端请假申请界面，需要填写哪些字段？哪些是必填？

- **A**：请假类型 + 开始日期 + 结束日期 + 原因（4个字段，均必填）
- **B**：请假类型 + 开始日期 + 结束日期 + 原因 + 紧急联系人姓名 + 联系电话（6个字段，均必填）
- **C**：请假类型 + 开始日期 + 结束日期 + 原因（4个字段）；附件（医院证明等）仅3天以上必填
- **D**：请假类型 + 开始日期 + 结束日期 + 原因 + 替岗人（下拉选择，仅替岗申请时显示）（5-6个字段）

推荐：**C**（4个基础字段满足大部分场景；3天以上需附件=Q3结论，保持一致；B的紧急联系人对越南工人不是必需品）

*grilling continue...*

## Q14: 员工端请假/替岗记录列表，需要支持哪些筛选条件？

- **A**：仅支持按请假类型筛选
- **B**：支持按请假类型 + 审批状态 + 日期范围筛选
- **C**：支持按请假类型 + 审批状态 + 日期范围 + 替岗人姓名筛选
- **D**：支持按请假类型 + 审批状态 + 日期范围 + 替岗人姓名 + 假期余额变动（正/负）筛选

推荐：**B**（审批状态 + 日期范围是最常用的排查组合；替岗人筛选+C的字段在员工视角不必要——员工查自己的记录不需要按替岗人筛）

*grilling continue...*

## Q15: 班组长审批请假时，系统需要展示哪些关键信息帮助判断？

- **A**：只显示请假类型、日期、原因
- **B**：显示请假类型、日期、原因 + **当前请假人该假期类型的剩余余额** + **当月累计请假天数**
- **C**：显示请假类型、日期、原因 + 请假人当月考勤统计（出勤/请假/迟到次数）
- **D**：显示请假类型、日期、原因 + 请假人该假期剩余余额 + 当月累计天数 + 当月考勤统计 + 历史请假记录

推荐：**D**（班组长审批时需要综合判断——余额看够不够用，当月天数看是否频繁请假，历史记录看是否有问题模式；信息完整才能做出合理决策）

*grilling continue...*

## Q16: 替岗人替岗当天，打卡记录挂在谁的名下？过MES工位扫描时识别的是谁？

- **A**：打卡挂在**替岗人**名下，MES工位扫描识别替岗人（替岗人用自己的账号打卡、过站）
- **B**：打卡挂在**被替岗人**名下，MES工位扫描识别被替岗人（替岗人是顶班，过站记录要挂在原员工名下）
- **C**：打卡挂在**替岗人**名下，但MES系统中同时记录替岗人和被替岗人的关联记录
- **D**：打卡挂在替岗人名下，但MES工位扫描识别被替岗人，替岗人作为"代班"备注

推荐：**A**（替岗人用自己的账号打卡是最自然的操作，MES记录也挂在替岗人名下；如果挂在被替岗人名下会造成考勤统计错乱）

*grilling continue...*

## Q17: 员工请假/替岗当天 MES 工位扫员工卡时，系统显示什么？

- **A**：显示员工姓名 + "请假中/替岗中" 状态，提示门禁/班组长，**但不拦截过站**
- **B**：显示员工姓名 + "请假中/替岗中" 状态，**直接拦截过站**，必须班组长刷员工卡才能放行
- **C**：不显示任何特殊提示，和正常出勤一样处理
- **D**：显示员工姓名 + "请假中/替岗中"，同时发送即时通知给班组长，班组长可以选择"放行"或"拦截"

推荐：**A**（请假生效不代表员工完全不能进车间——可能有特殊情况需要回来处理；不拦截但提示明显，班组长可人工干预；B的硬拦截会造成合法请假员工被卡在车间外的投诉）

*grilling continue...*

## Q18: 员工在无网络（离线）状态下提交请假申请，系统怎么应对？

- **A**：离线状态下禁止提交，系统提示"请连接网络后重试"
- **B**：离线状态下允许员工填写申请，系统暂存在本地；联网后自动上报，审批流程正常进行
- **C**：离线状态下允许员工填写申请并提交，系统标记为"草稿"；联网后员工需手动点"重新提交"
- **D**：离线状态下员工无法填写，系统显示上次缓存的请假余额和历史记录供查看

推荐：**B**（离线暂存 + 联网自动上报 = 最少操作负担；C需要手动重新提交，增加员工操作成本；A完全阻断不合理——车间内网络不稳定是常态）

*grilling continue...*
