# WMS 电子流对接 OA 方案（决策版）

**日期**：2026-10-21
**范围**：D:/WMS-20261019（业务系统）←→ D:/OA 协同管理平台（审批引擎）
**依据**：`docs/OA电子流对接调研-契约与差异清单.md`（逐行核对 OA flow.js 与 WMS 审批点）

---

## 📌 TL;DR

- OA 的流程引擎（版本化定义、多级/会签、转办/加签/撤回、催办、台账、SLA）**能力足够**，可以作为 WMS 的统一审批引擎；
- 但 OA **几乎没有对外集成面**：没有业务单据字段、没有回调、没有 API Key、没有批量审批；
- 结论：**先补 OA 的 6 项集成能力，再按「单级流程 → 多级流程 → MRB」分期迁移；全部迁完后下线 WMS 审批功能**；
- 另发现 WMS 一处 **审批权限可绕过** 的缺陷（roleCode 匹配方式错误），无论是否接 OA 都应先修。

---

## 1. 目标架构

```
WMS（业务）                         OA（审批）
┌──────────────────┐   提交实例    ┌──────────────────┐
│ 领料/超领/补料    │ ───────────▶ │ flow_instance     │
│ 盘点/调拨/IQC/退料│              │ flow_task（待办）  │
│ 业务状态机        │ ◀─────────── │ 会签/转办/催办     │
└──────────────────┘  回调/轮询    └──────────────────┘
        │                                   │
        └──── 统一待办/我的审批（OA 页面） ──┘
```

原则：

1. **审批只在 OA 做**，WMS 不再实现审批 UI，只保留「状态 + 去 OA 审批」入口；
2. **WMS 保留业务状态机**（如 approved → issued → received），审批结果回写驱动业务流转；
3. **一次提交一个 OA 实例**，WMS 侧存 `oa_instance_id` 做唯一映射；
4. 灰度开关按 `bizType` 控制，老单据走原逻辑。

## 2. 对接契约（最小可用）

### 2.1 WMS → OA 提交

```
POST /api/instances      （OA 现有接口）
Body: { definitionId, title, formData, submitNow: true, subjectUserId }
formData 固定放：{
  wmsBizType, wmsBizNo, wmsBizId, wmsUrl,
  materialCode, qty, workSection, applicant, ...业务字段
}
```

WMS 侧新增字段：`oa_instance_id`、`oa_status`、`oa_synced_at`（各业务表或统一关联表）。

### 2.2 OA → WMS 回传（需新增）

- **首选 webhook**：OA 在实例状态变更/任务完成时 POST `WMS /api/integration/oa/callback`，
  带 `instanceId / status / nodeIndex / approver / comment / timestamp` + HMAC 签名；
- **兜底轮询**：WMS 每 60s 拉一次在途实例状态，做对账（防回调丢失）；
- 幂等键：`instanceId + nodeIndex + status`，重复回调直接忽略。

### 2.3 状态映射

| OA `flow_instance.status` | WMS 单据状态 |
|---|---|
| draft / running | `pending_approval`（审批中） |
| approved | `approved`（业务继续走 issued/received） |
| rejected | `rejected`（退回发起人） |
| canceled | `cancelled` |

## 3. 流程迁移清单

| 流程 | 现有节点 | 能否复用 OA | 结论 |
|---|---|---|---|
| 领料审批 | 单级（生产主管） | ✅ | 一期 |
| 超领审批 | 单级 | ✅ | 一期 |
| 补料审批 | 单级 | ✅ | 一期 |
| IQC 报告审批 | 单级 | ✅ | 二期 |
| 盘点审批 | 单级 | ✅ | 二期 |
| 库存调拨 | 单级 | ✅ | 二期 |
| 生产退料（退料→IQC→入库） | 串行多角色 | ⚠️ 可用两段流程拼 | 二期 |

## 6. ⚠️ 必须先修的 WMS 缺陷

调研发现：角色查询用 `platform_user_id` 匹配，而该字段多数账号为空/不一致，
存在 **审批权限判断被绕过** 的风险（详见调研报告 §7）。这与是否接 OA 无关，建议 P0 一并修。

| 风险 | 影响 | 对策 |

## 4.3 MRB 迁移方案（补充）

MRB 与其他流程不同：它有「评审员会签 + 逐条处置结论 + 逐箱分配」，不能整单搬。

**拆分原则：方案在 WMS，签署在 OA。**

| 环节 | 归属 | 说明 |
|---|---|---|
| 方案制定（处置方式、逐箱分配、评审员名单） | **WMS** | 现有页面保留，SQE 操作 |
| 提交评审 | WMS → OA | 生成 OA 实例，`formData` 带：MRB 号、物料/批次/数量、处置明细表、每箱分配、评审员名单 |
| 评审员会签 | **OA** | 每人一条任务，`assign: user_selected` + `min_approvals = 评审员人数`；意见写 `comment`，结论写 `formData.review_result` |
| IQC 主管预审 | **OA** | 单级节点 |
| 质量经理终审 | **OA** | 单级节点，通过即终态 |
| 结论回写与库存处置 | **WMS** | 回调驱动：写 `mrb_reviewer.review_result/opinion`、推进 `mrb_review.status`、执行处置链 |

关键约束：

1. **整单结论（已确认）**：OA 表单用 `table` 字段**只读展示**处置明细，评审员对整单给结论：
   - **同意**：无需填写意见，一键通过；
   - **驳回**：**必须填写意见**（OA 需新增校验：`action='reject'` 且 `comment` 为空 → 400）。
   一个 MRB 问题 = 一条电子流程，不做「WMS 填一部分、OA 签一部分」的混合模式。
2. **状态收敛**：OA 只有 `running/approved/rejected`，WMS 的 `pending_review/pending_pre_approval/pending_final` 由**当前节点**推导（OA 返回 `current_index` + 节点名），不再作为独立状态来源。
3. **撤回/驳回**：OA 撤回 → WMS 回 `draft/pending_review`；驳回 → 回到 SQE 改方案，评审意见清空（沿用现有逻辑，由回调触发）。
4. **幂等**：MRB 号 + 实例 ID 唯一；重复回调只应用一次。

## 4.35 在途单统一迁移（D5：全部迁 OA）

切换时点存在在途单（当前 1 张 MRB 在评审 + 若干领料单），**统一迁移**，不等待。

**迁移步骤（一次性脚本 + 人工复核）：**

1. **冻结窗口**（30 分钟）：停 WMS 审批入口，禁止新审批动作；
2. **导出在途单**：按 bizType 取 `status in (pending_approval, pending_review, pending_pre_approval, pending_final)` 的单据 + 明细 + 已产生的审批意见；
3. **在 OA 建实例**：用对应流程定义创建实例，`formData` 写入业务快照与历史意见；`submitNow=true`；
4. **推进到当前节点**：管理员用 `POST /api/instances/:id/assign-node` 把实例推进到与原单一致的节点（如 MRB 的「评审员会签」或「质量终审」）；
5. **回写映射**：WMS 记录 `oa_instance_id / oa_status`，单据状态改为「迁移中（OA）」；
6. **核对**：逐单比对「原当前节点 = OA 当前节点」，不一致的人工修正；
7. **解冻**，恢复入口（此后只允许在 OA 审批）。

**注意：**

- 迁移的实例 `applicant_id` 用原申请人；OA 无对应账号时落到服务账号并在 `formData.applicant_name` 保留原名；
- 历史审批意见作为 `flow_log` 备注或首次 `extraFields` 写入，保证审计链不断；
- 迁移脚本必须**可重跑**（按 bizNo 幂等），失败单单独列白名单人工处理。

## 4.4 切换后下线 WMS 审批（D4）

分三步，保证业务不中断：

1. **双轨期**：新单走 OA，在途单走 WMS；列表同时显示两种状态；
2. **只读期**：所有单走 OA 后，WMS 审批按钮隐藏，仅保留「查看 + 去 OA 审批」；
3. **下线**：审批接口返回 410（或直接移除路由），菜单入口改为跳 OA 待办；历史审批记录保留只读。

下线清单：9 个 approve 接口、5 个审批页面/按钮、审批相关权限点、审批消息通知。
