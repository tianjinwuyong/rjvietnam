# 员工岗位责任与人事治理制度

## 1. 制度目标

本制度将岗位责任、考勤、绩效、奖励、晋升、降职、调岗、调薪、加班、休假、停职、辞职和辞退纳入统一的人事闭环。任何人事决定都必须有事实、依据、审批、员工知悉、执行结果和审计记录。

## 2. 岗位责任书

- 每个岗位采用版本化责任书，包含岗位目的、工作责任、权限边界、KPI、安全责任和任职资格。
- 新版本必须先审批再生效，旧版本自动退役，不覆盖历史。
- 生效后，系统向该岗位所有在职员工生成签收任务。
- 员工可“确认签收”或“拒绝签字并说明原因”；拒绝签字不删除记录，也不能被伪造成已签收。
- 未签收责任书的员工不得被视为已经接受新职责。

## 3. 考勤、请假与加班

- 考勤原始记录、修正记录、请假单和加班单分别保存，修正不得覆盖原始数据。
- 请假和加班由原申请触发人事事项；审批完成后，系统回写原申请状态。
- 加班必须有事前申请或经批准的补录原因，不能只凭月末口头确认。
- 考勤异常可作为调查线索，但不得自动成为辞退、降薪或降职的唯一依据。

## 4. 绩效与改进

- 绩效指标必须来源于已生效岗位责任书，且在考核期开始前告知员工。
- 评分保留指标、目标、数据来源、评分人、复核人和证据。
- 低绩效优先进入绩效改进计划，明确目标、辅导人、期限和复核结果。
- 单次评分不能直接触发辞退或降薪；高风险事项必须进入多级审批和申诉程序。

## 5. 奖励、晋升、调岗和调薪

- 奖励：线长与部门经理批准；涉及金额时必须进入奖励/薪资台账。
- 晋升与加薪：部门经理、人事、财务批准。
- 调岗与绩效改进：部门经理、人事批准。
- 降职与降薪：部门经理、人事、总经理批准，属于高风险事项。
- 调岗、晋升和降职执行后，系统更新员工岗位并写入工作履历。
- 调薪执行后生成带生效日期的薪资条款，旧条款退役，历史永久保留。

## 6. 辞职、停职与辞退

- 辞退、停职、降职和降薪必须具备明确原因代码、事实说明和证据附件。
- 辞退必须经部门经理、人事和总经理审批。
- 执行前应完成员工知悉；员工拒签时记录“拒绝签字”和原因，不得代签。
- 员工可提交申诉和补充证据。申诉期间由人事决定是否暂停执行。
- 执行后保留离职日期、原因、人事事项单、审批、知悉、申诉和审计链。
- 实际使用前，人事部门应依据越南现行劳动法律、劳动合同和公司规章完成法律复核。

## 7. 系统状态

`DRAFT → PENDING_APPROVAL → APPROVED → EXECUTED`

驳回进入 `REJECTED`；申诉进入 `APPEALED`；取消进入 `CANCELLED`。所有状态变化均写入不可遗漏的审计表。

## 8. 审批矩阵

| 事项 | 必需审批 |
|---|---|
| 奖励、警告 | 线长、部门经理 |
| 绩效改进、调岗 | 部门经理、人事 |
| 晋升、加薪 | 部门经理、人事、财务 |
| 降职、降薪、停职、辞退 | 部门经理、人事、总经理 |
| 加班、休假 | 线长、部门经理 |

## 9. 系统实现位置

- 管理界面：管理系统 → 人事 → 岗位责任与人事治理
- 责任书：`hr_position_responsibility_versions`
- 员工签收：`hr_responsibility_acknowledgements`
- 人事事项：`hr_personnel_actions`
- 多级审批：`hr_personnel_action_approvals`
- 员工知悉：`hr_personnel_action_employee_ack`
- 申诉：`hr_personnel_action_appeals`
- 调薪条款：`hr_employee_compensation_terms`
- 执行结果：`hr_personnel_action_effects`
- 全程审计：`hr_personnel_action_audit`
