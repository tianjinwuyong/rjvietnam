# P0：OA 对接契约与改造清单

**日期**：2026-10-21
**范围**：打通「领料审批」单流程，验证提交 → 审批 → 回调 → 业务流转全链路
**前置决策**：D1 接受 OA 补集成能力；D2 MRB 迁 OA；D3 审批人按 OA 组织；D4 迁完下线 WMS 审批；D5 在途单统一迁移

## 1. OA 侧改造（字段级）

### 1.1 实例增加业务标识（O1）

```sql
ALTER TABLE flow_instance
  ADD COLUMN IF NOT EXISTS biz_system varchar(20),   -- 'WMS'
  ADD COLUMN IF NOT EXISTS biz_type   varchar(50),   -- 'picking_approval' 等
  ADD COLUMN IF NOT EXISTS biz_key    varchar(100);  -- WMS 业务单号

-- 同一业务系统、同一单据只允许一条在途实例（幂等基础）
CREATE UNIQUE INDEX IF NOT EXISTS uq_flow_instance_biz
  ON flow_instance (biz_system, biz_type, biz_key)
  WHERE status IN ('draft','running');
```

`POST /api/instances` 请求体新增 `bizSystem / bizType / bizKey`（可选，兼容现有内部流程）。

### 1.2 Webhook 回调（O2）

```sql
CREATE TABLE IF NOT EXISTS flow_webhook_outbox (
  id bigserial PRIMARY KEY,
  instance_id bigint NOT NULL,
  event varchar(30) NOT NULL,        -- submitted/approved/rejected/withdrawn/terminated/node_passed
  payload jsonb NOT NULL,
  target_url text NOT NULL,
  status varchar(20) NOT NULL DEFAULT 'pending', -- pending/sent/failed
  attempts int NOT NULL DEFAULT 0,
  next_retry_at timestamptz,
  last_error text,
  created_at timestamptz DEFAULT now()
);
```

- 在 `advance()` 终态、`reject`、`return`、`terminate`、`withdraw` **5 处**写入 outbox（事务内）；
- 定时任务每 10s 取 `pending` 投递，失败指数退避（10s/30s/2min/10min，最多 8 次）；
- 签名：`X-OA-Signature = HMAC-SHA256(body, secret)`，WMS 侧验签。

### 1.3 服务账号 / API Key（O3）

```sql
CREATE TABLE IF NOT EXISTS sys_api_key (
  id bigserial PRIMARY KEY,
  name varchar(50) NOT NULL,
  key_hash varchar(128) NOT NULL,     -- sha256(key)
  permissions text[] NOT NULL DEFAULT '{}',
  active boolean NOT NULL DEFAULT true,
  created_at timestamptz DEFAULT now()
);
```

- 鉴权中间件支持 `X-Api-Key`，命中后注入 `req.user = { id: 服务账号, isApi: true }`；
- 服务账号仅需 `flow:view/submit/approve` 三个权限（批量审批用）。

### 1.4 批量审批（O4）

```
POST /api/tasks/batch-approve
{ taskIds: number[], action: 'approve'|'reject', comment?: string }
→ { success: number[], failed: [{ id, reason }] }
```

逐条独立事务，**部分失败不影响其他**（参考现有 IQC 批量返回结构）。

### 1.5 驳回意见必填（O7）

`approveTask()` 中新增：

```js
if (action === 'reject' && !String(comment || '').trim()) {
  throw new BizError('驳回必须填写意见');
}
```

### 1.6 审批人按 OA 组织（O5）+ 回跳（O6）

- 节点 `assign` 使用 OA 现有表达式：`dept_leader` / `role:<code>` / `user:<id>` / `user_selected`；
- 实例详情接口返回 `returnUrl`（来源系统回跳地址，存 `form_data.return_url`）。

## 2. 接口契约

### 2.1 WMS → OA 提交

```
POST /api/instances
Headers: X-Api-Key: <key>
Body: {
  definitionId: 123,
  title: "领料审批 PK202610210001",
  bizSystem: "WMS",
  bizType: "picking_approval",
  bizKey: "PK202610210001",
  submitNow: true,
  subjectUserId: 456,              // WMS 申请人对应的 OA 用户
  formData: {
    return_url: "http://wms/production/picking-approval?no=PK202610210001",
    wms_biz_no: "PK202610210001",
    work_order_no: "WO202610210001",
    work_section: "SMT",
    applicant_name: "阮文A",
    total_qty: 1200,
    items: [{ material_code: "0.01.09.00.0338P", material_name: "插件固态电容", qty: 100, unit: "PCS" }]
  }
}
→ { code:0, data:{ id, instance_no, status } }
```

### 2.2 OA → WMS 回调

```
POST /api/integration/oa/callback
Headers: X-OA-Signature: <hmac>
Body: {
  event: "approved",
  instanceId: 9001,
  instanceNo: "PICK-20261021-000001",
  bizSystem: "WMS", bizType: "picking_approval", bizKey: "PK202610210001",
  status: "approved",
  nodeIndex: 2,
  approver: { oaUserId: 456, name: "生产主管" },
  comment: "",
  occurredAt: "2026-10-21T10:00:00+07:00"
}
```

WMS 处理：验签 → 按 `bizType + bizKey` 找单 → 幂等校验（`instanceId+event+nodeIndex`）→ 更新状态 → 触发业务后续（如发料）。

### 2.3 状态映射

| OA | WMS |
|---|---|
| draft | draft |
| running | pending_approval |
| approved | approved |
| rejected | rejected |
| withdrawn | draft（可重新提交） |
| terminated | cancelled |

### 2.4 错误码

| 场景 | 返回 |
|---|---|
| 业务单已有在途实例 | 409 `BIZ_DUPLICATE` |
| 申请人无 OA 账号 | 400 `USER_NOT_MAPPED` |
| 节点无审批人 | 实例挂起，OA 通知管理员 |
| WMS 验签失败 | 401 `BAD_SIGNATURE` |

## 3. WMS 侧改动（P0 范围）

```sql
ALTER TABLE picking_order
  ADD COLUMN IF NOT EXISTS oa_instance_id bigint,
  ADD COLUMN IF NOT EXISTS oa_status varchar(20),
  ADD COLUMN IF NOT EXISTS oa_synced_at timestamptz;

ALTER TABLE sys_account
  ADD COLUMN IF NOT EXISTS oa_user_id bigint;   -- 对应 OA org_user.id
```

- 提交时先写本地 `oa_status='submitting'`，成功回填 `oa_instance_id`；
- 失败写 `oa_status='submit_failed'`，页面可重试（幂等）。

## 4. 「领料审批」验收用例

| # | 用例 | 预期 |
|---|---|---|
| 1 | 正常提交 | OA 生成实例，状态 running，WMS 单状态 pending_approval，台账可查 |
| 2 | 审批通过 | OA completed → 回调 → WMS approved → 可发料 |
| 3 | 驳回不填意见 | OA 返回 400「驳回必须填写意见」 |
| 4 | 驳回填意见 | OA rejected → 回调 → WMS rejected，列表可见意见 |
| 5 | 重复提交同一单 | 第二次返回 409 `BIZ_DUPLICATE`，不产生第二条实例 |
| 6 | 申请人在 OA 不存在 | 提交返回 400 `USER_NOT_MAPPED`，页面提示补账号 |
| 7 | 回调重放 | 同一 `instanceId+event` 回调两次，WMS 只生效一次 |
| 8 | 回调丢失 | 关掉 webhook，审批完成后 60s 内由轮询对账补上状态 |
| 9 | OA 撤回 | WMS 回到 draft，可修改重新提交 |
| 10 | 批量审批 | 3 张单批量通过，其中 1 张已审批 → 返回成功 2 失败 1 |
