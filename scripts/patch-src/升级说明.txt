------------------------------------------------------------------------
【安全与稳定性修复】

7. 账号批量导入（10-15）
   - 系统管理 -> 账号管理 新增「下载导入模版」与「批量导入」

8. 修改密码（10-16）★ 请见第十一节
   - 每个账号都可以自己改自己的密码，不再只能找管理员重置
   - 电脑端入口：右上角当前登录人按钮 -> 「修改密码」
   - PDA 入口：首页底部「修改密码」按钮
   - 首次登录（或被管理员重置密码后）会强制弹出改密框，
     改完才能继续使用，弹窗不能关闭、不能用 Esc 跳过
   - 新密码要求 6-32 位、两次一致、不能与原密码相同，
     并拒绝 123456 / 888888 / admin / password 这类简单口令
   - 改密与重置都会记入操作日志，日志中不保存密码明文
   - 本功能只改密码，不需要改数据库，也不需要新的依赖

【体验修复】
9. PDA 扫码声音与提示统一（10-16）★ 请见第十节
   - 此前只有「扫码收货」「领料拣货」两个页面有「滴」声提示音，
     移库 / 调拨 / 上架 / 补料 / 发料 / 库存盘点等页面扫码成功时
     只有语音、没有提示音，在嘈杂车间容易被忽略

         成功  ->  高音「滴」+ 语音「OK」

     改成短口令 + 弹窗文字，听得清也看得清
   - 失败弹窗不再 2 秒自动消失，会一直留到点【确认】为止，
     便于看清原因（成功弹窗仍 2 秒自动消失，不打断连续作业）
   - 点【确认】后焦点自动回到扫码入口：扫码枪 / 键盘扫的回到输入框，
     摄像头扫的重新打开摄像头，可以直接接着扫下一条
   - 发料 / MRB / 库存盘点三个页面此前失败时完全没有声音，已补齐；
     同时修掉了「只有声音、不弹窗」几处漏网分支

10. 系统初始化（10-16）★ 请见第十二节，请先读完再操作
   - 系统管理 -> 系统初始化：一个按钮把系统恢复到「刚装好」的状态
   - 清空全部业务数据与账号，只保留 admin 一个账号

   - 执行后所有已登录用户被强制退出，须用 admin 重新登录并改密码
   - 本功能不需要改数据库结构，也不需要新的依赖

七、★ 升级前必须先确认：MRB 终审权限
------------------------------------------------------------------------
本次给 MRB 终审增加了角色限制。升级后只有以下三种角色可以终审：

      quality_manager    品质经理
      iqc_manager        IQC主管
      admin              管理员

请先在服务器上执行以下 SQL，确认现场实际使用哪个账号做终审：

      SELECT account, name, role_code FROM sys_account ORDER BY role_code;

如果该账号的 role_code 不属于上述三类，升级后点击终审会被拒绝，
返回 403「您没有权限执行此操作」。

遇到这种情况请先不要升级，联系开发人员把该角色加入白名单后再升级。

九、账号批量导入怎么用（新功能）
------------------------------------------------------------------------
1. 进入 系统管理 -> 账号管理
2. 点「下载导入模版」，得到一个 Excel 文件，含两个工作表：
     表 1「账号导入」  —— 在这里填写，第 1 行是表头，第 2 行是示例
     表 2「填写说明」  —— 填写规则 + 系统当前可选的角色清单
3. 在表 1 填写。第 2 行的示例请务必删除或替换（不删会导致整份文件被拒绝）
4. 保存为 .xlsx / .xls / .csv
5. 回到账号管理页，点「批量导入」，选择该文件

  必填列： 账号、姓名、角色编码
  可空列： 所属工段（smt / dip / assembly / packing）、初始密码（留空为 123）

  账号只能包含字母、数字、下划线、点、连字符；不能使用 admin。
  角色编码必须来自表 2 的清单，也可以直接填中文角色名称。

   ★ 只要有一行不合法，整份文件都不会导入（一个账号都不建），
    页面会逐行列出错误原因，改完再传一次即可。

  ★ 导入的账号第一次登录时会被要求修改初始密码（见第十一节），
    因此可以放心把初始密码统一定为 123，不必逐个单独设置。

十、扫码声音提示怎么用（10-16 统一补齐）
------------------------------------------------------------------------
1. 浏览器规则：出于安全限制，页面必须有过一次点击才允许出声。
   打开 PDA 页面后请先随便点一下屏幕，再开始扫码。

2. PDA 首页底部有【音频测试】按钮，点一下会响一声并播报语音。
   如果这里都听不到，说明是设备侧问题，按下面第 4 条排查。

3. 声音规则（所有界面完全一致，不随界面语言变化）：
   扫码 / 操作成功  ->  高音「滴」+ 语音「OK」
   扫码 / 操作失败  ->  低音「滴」+ 语音「NG」，并弹出失败原因

   覆盖范围：扫码收货、收货查询、库内移库、库存调拨、不良品移动、
             库存查询、盘点登记、领料拣货、补料作业、发料作业、
             MRB 评审、上架作业，以及电脑端的收货扫码与库内移库页面。

4. 失败弹窗与「接着扫下一条」（本次新增）
   扫码失败时会弹出一个写有具体原因的窗口，例如「源地址码不存在」。
   - 这个窗口不会自己消失，要看清原因后点【确认】关闭
   - 点【确认】后焦点会自动回到刚才扫码的位置：
        用扫码枪 / 手工输入的  ->  光标回到输入框，直接扫下一条即可
        用摄像头扫的          ->  摄像头重新打开，直接对准下一条即可
   - 成功时的提示窗口仍然是 2 秒自动消失，不会打断连续作业

5. 听不到声音时依次检查：
   - 设备是否处于静音 / 振动模式
   - 媒体音量是否为 0（注意不是铃声音量）
   - 打开页面后是否点过屏幕（见第 1 条）
   - 是否用微信等内置浏览器打开（建议改用系统自带浏览器）
   - 是否升级后只刷新了页面：请按 Ctrl+Shift+R 强制刷新，
     或清一次浏览器缓存，否则加载的仍是旧版页面

十一、修改密码怎么用（10-16 新功能）
------------------------------------------------------------------------
一、从哪里改
  1. 电脑端：点右上角显示当前登录人的按钮，菜单里选「修改密码」
  2. PDA 端：首页底部「修改密码」按钮

二、怎么填
  需要填写三项：原密码、新密码、确认新密码。
  新密码必须同时满足：
     - 长度 6-32 位
     - 两次输入完全一致
     - 不能与原密码相同
     - 不能过于简单（123456、888888、admin、password 等会被拒绝）
  不满足时窗口里会直接显示中文（越南文 / 英文界面下显示对应语言）的原因。

三、改完会怎样
  - 立即生效，下次登录请使用新密码
  - 该账号的「首次登录」标记被清除，不会再被强制改密
  - 操作会记入系统管理 -> 操作日志（动作为 change_password）
  - 日志里不保存密码内容，只记录谁在什么时间改了密码

四、★ 升级后首次登录提醒（重要，请提前通知现场）
  本次升级启用了「首次登录强制改密」。判断依据是账号表里的
  「首次登录」标记，而当前系统里绝大多数账号的该标记都处于开启状态，
  因此升级后：

     - 每个账号第一次登录时，都会先弹出「请先修改初始密码」窗口，
       必须改完密码才能进入系统
     - 这个窗口没有关闭按钮，按 Esc、点窗口外面都关不掉
     - 包括 admin 管理员账号在内

  这不是故障。建议按下面的顺序推进：
     1. 管理员先登录并完成改密，确认流程正常
     2. 再通知现场人员各自登录改密，或由管理员在账号管理里
        逐个点「重置密码」后交由本人登录修改
     3. 改完的账号不会再被要求改密

五、关于管理员重置密码
  系统管理 -> 账号管理 -> 「重置密码」会把该账号密码改回 123，
  并重新打开「首次登录」标记，该账号下次登录时必须再改一次。
  admin 管理员账号不能被重置，需要本人在「修改密码」里自行修改。

十二、系统初始化怎么用（10-16 新功能）
------------------------------------------------------------------------
一、它做什么
  系统管理 -> 系统初始化，一个按钮把系统恢复成「刚装好」的状态：
     - 清空全部业务数据：物料主数据、供应商档案、仓库与地址码档案、
       BOM、IQC 检验配置、库存、收料单、领料单、工单、盘点、
       调拨、MRB、发料、退料、返工等全部记录
     - 清空账号，只留下 admin 一个
     - 操作日志一并清空（只保留本次初始化这一条记录）
     - 所有单据号从 1 重新开始（首张收料单仍是 RC-0001）
  保留不动的三项（它们决定系统还能不能用）：
     - 角色定义与菜单权限（系统管理里 17 个角色的权限配置）
     - 系统参数（IQC 目标值、好坏品仓库编码等运行配置）
     - 数据库迁移记录

二、三道防线（防止误触）
  这道按钮一旦点下去无法撤销，因此设了三层确认：
     第 1 层：菜单项只有 admin 角色看得到
     第 2 层：弹窗里必须手动输入确认短语「初始化」，
              输错则确认按钮保持灰色、点不动
     第 3 层：还要输入当前登录密码，密码由服务端重新核对，
              密码不对会提示「当前登录密码不正确」，系统不会做任何改动
  三层都通过才会真正执行。

三、执行过程会怎样
  - 整个过程在一个数据库事务里完成，中途出错会整体回滚，
    不会出现「清了一半」的状态
  - 执行成功后页面提示清空了多少张表 / 多少行 / 删除多少个账号，
    然后自动退出登录、回到登录页
  - 此时用 admin / admin 登录（首次登录会要求修改密码）

四、★ 使用前请务必注意
  1. 这是不可撤销的操作。请在执行前先做好数据库备份
     （备份方法见《部署手册》或联系开发人员）。
  2. 执行后所有人被强制退出，需要重新登录，请提前通知现场。
  3. 仓库档案与地址码会被一并清空：执行后必须先建仓库档案、
     再建地址码，否则扫码收料、移库、调拨、库存查询无法使用。
  4. 初始化会作废此前签发的所有登录凭证（旧令牌全部失效），
     这是安全设计，不是故障。

五、适合什么时候用
  - 交付前的最后清理：把测试期间产生的数据全部清掉，交出去就是一个干净系统
  - 现场数据需要重来：盘点彻底对不上、想做一次全新开始时
